# 合同条款重编号工作台

粘贴含“第X条”定义与条款引用的合同纯文本，系统解析引用关系、标出**缺失引用**与**重复编号**；
提交“旧编号 → 新编号”的批量映射后，先给出**逐处变更预览**，确认后以**单个 SQLite 事务原子
同步**条款标题与正文引用。支持交换、环形改号以及 1/10 等前缀相近编号；检测到冲突时**拒绝写入**
并给出冲突位置。

此外支持**条款裁撤**：勾选一个或多个已定义条款，系统按标题边界识别各条款正文、构建条款引用图，
列出直接引用待删条款的位置及沿引用链传递受影响的条款；提交前每个指向待删条款的引用都必须映射到
一个**未删除**条款，无引用的待删条款可直接裁撤。确认后同样在**单个 SQLite 事务**中更新正文与
撤销历史，与改号共用同一个栈式撤销入口。

可**撤销**最近一次操作（改号或裁撤，栈式可连续撤销），并**导出**处理后的文本。

技术栈：React + TypeScript（Vite）· Node.js + Express · SQLite（better-sqlite3）· Docker / Compose。

## 一条命令启动

```bash
docker compose up --build
```

首次运行会自动：构建并安装依赖 → 构建前端 → 创建 SQLite 数据库（自动建表）→ 启动服务。
随后打开 **http://localhost:3000** 即可使用（容器内监听 `0.0.0.0:3000`，宿主机端口可在
`docker-compose.yml` 的 `ports` 中调整，如 `"8080:3000"` 则改为访问 http://localhost:8080 ）。
停止后数据保留在 Docker 卷 `contract-data` 中。

> 不想用容器？本地开发见文末“本地开发（不用 Docker）”。

## 使用流程

1. **粘贴文本**：把合同纯文本粘入文本框（可点“载入示例”体验，示例内含重复定义、缺失引用、
   第1条与第10条；另有“无冲突示例”含清晰引用链与循环引用，适合体验条款裁撤）。点击“解析并建立工作台”。
2. **检查解析结果**：
   - 行首（允许前导空白、后跟空白或标点）的“第X条”识别为**条款定义（标题）**；
   - 其余所有“第X条”出现识别为**引用**；
   - 引用了未定义编号 → ❌ 缺失引用；同一编号有多个标题 → 重复编号（标出首次/再次出现的行）。
3. **条款裁撤（可选）**：见下节“条款裁撤流程”。
4. **改号映射（可选）**：每行填写旧编号与新编号（正整数）。可点按钮快速生成“交换”或“环形改号”。
5. **生成预览**：逐处列出“标题/引用、行列位置、改动前后、上下文”，并可展开查看高亮后的全文。
6. **确认提交**：后端再次校验，通过后在一个事务内写入撤销历史并更新正文，保证原子性。
7. **撤销 / 导出**：撤销最近一次操作（恢复操作前正文并弹出历史栈顶）；导出当前文本为 `.txt`。

## 条款裁撤流程

1. 在“条款裁撤”面板勾选一个或多个待删条款，点击**分析引用影响**。
2. 系统按**标题边界**切出每个条款的完整区块（标题行到下一标题行之前；首个标题之前为“序言”，永不删除），
   并构建引用图：
   - **删除集合**：每个待删条款的标题、行号，以及幸存正文中指向它的引用数；无引用条款标注“可直接裁撤”。
   - **直接引用**：列出幸存文本（含序言）中每一处指向待删条款的引用：引用编号、所在条款、行列位置、上下文。
   - **传递影响**：沿引用链反向可达待删条款的幸存条款，给出完整引用链（如 `第3条→第2条→第1条`）；
     循环引用会被识别且不会造成死循环。
3. **逐组指定替代条款**：对每个被幸存文本引用的待删编号，下拉选择一个**未删除的已定义条款**；
   位于待删区块内部的引用随区块移除，无需映射；无引用的条款无需映射。
4. 点击**生成裁撤预览**：
   - **删除区块**：每个区块的删除行范围、相邻标题（上一条/下一条或序言/文末）与将删除的完整文本；
   - **逐处引用替换**：所在条款、行列位置、改动前后、上下文；
   - 可展开查看裁撤后的全文（高亮替代目标编号）。
5. **确认裁撤并原子提交**：后端重新校验，通过后在单个 SQLite 事务中写入撤销历史、更新正文；
   随后可用第 5 步的“撤销最近一次操作”一键恢复（撤销记录中标注操作类型为改号或裁撤）。

### 裁撤拒绝规则（HTTP 409，响应含行列位置，不产生任何写入）

| 情形 | code | 说明 |
| --- | --- | --- |
| 未勾选任何条款 / 编号非正整数 | `EMPTY_SELECTION` / `INVALID_NUMBER` | 请求形态校验 |
| 待删编号没有标题定义 | `DELETE_NOT_DEFINED` | 引用不能作为裁撤源头 |
| 同一待删条款给了多个替代 | `DUP_REPLACE_SOURCE` | 一个编号只能映射一个目标 |
| 存在未映射的幸存引用 | `UNRESOLVED_REFERENCE` | 按待删编号聚合全部引用位置返回 |
| 替代目标也在删除集合中 | `REPLACEMENT_DELETED` | 附目标标题位置 |
| 替代目标在文本中未定义 | `REPLACEMENT_UNDEFINED` | 必须指向已定义条款 |
| 给了多余的替代映射 | `UNNEEDED_REPLACEMENT` | 幸存文本并无引用（含引用全在待删区块内的情况） |
| 文本存在重复标题定义 | `DUPLICATE_DEFINITION` | 区块边界不唯一，附每处标题行列位置 |
| 文本存在指向未定义编号的引用 | `MISSING_DEFINITION` | 引用图不完整，附全部引用位置 |

> 相邻标题（中间无空行）、首条/末条裁撤、空正文条款、多条同时删除（区块内互引随区块消失）
> 均已在服务端测试中覆盖；裁撤末条时文末多余空行会收敛为一个换行（原文无尾换行则不添加）。

### 编号风格

- 同时支持**阿拉伯数字**（第1条、第12条）与**中文数字**（第一条、第十二条、壹拾贰条、含“两”）。
- 每处出现**沿用自身原有风格**：原文“第十条”改成 3 后写为“第三条”；原文“第10条”写为“第3条”。
- 交换与环形不依赖替换顺序：实现上以完整 token（带“第/条”定界）为单位重新扫描、单遍重建，
  因此“第1条”永远不会误伤“第10条”，1→2 与 2→1 同时提交也安全。

## 冲突拒绝规则（HTTP 409，响应含行列位置，不产生任何写入）

| 情形 | 说明 |
| --- | --- |
| 映射为空 / 行列格式非法 | 旧、新编号都必须是正整数 |
| 同一旧编号出现多次 | 一个源只能有一个目标 |
| 新编号在映射内重复 | 两个源不能争用同一目标 |
| 旧编号在文本中没有标题定义 | 引用不能作为改号源头 |
| 新编号撞上**未参与**本次映射的既有条款 | 会产生重复定义，拒绝并给出既有标题位置 |

已在映射内部的编号互换/环形（如 1→2、2→1，或 1→2→3→1）属于合法重排，会被正确接受。

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_PATH` | 容器内 `/data/contract.db` | SQLite 文件路径，启动时自动建库建表 |

Compose 已把 `/data` 挂载到命名卷 `contract-data`，容器重建后数据不丢失。

## HTTP API（摘要）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/analyze` | 无状态解析文本，返回定义/引用/问题 |
| POST | `/api/documents` | 建立工作台文档并解析 |
| GET | `/api/documents/:id` | 获取文档与最新解析 |
| PUT | `/api/documents/:id` | 手工修改原文（清空撤销栈） |
| POST | `/api/documents/:id/renumber/preview` | 逐处变更预览（只读，冲突返回 409） |
| POST | `/api/documents/:id/renumber/commit` | 原子提交改号 |
| POST | `/api/documents/:id/removal/impact` | 裁撤影响分析：引用图、直接引用与传递影响（只读） |
| POST | `/api/documents/:id/removal/preview` | 删除区块 + 逐处替换预览（只读，冲突返回 409） |
| POST | `/api/documents/:id/removal/commit` | 原子提交条款裁撤（与改号共用历史表/撤销入口） |
| POST | `/api/documents/:id/undo` | 撤销最近一次操作（改号或裁撤） |
| GET | `/api/documents/:id/export` | 导出处理后的纯文本 |

提交/预览请求体：`{ "mapping": [{ "from": 1, "to": 2 }, { "from": 2, "to": 1 }] }`。
裁撤请求体：`{ "deletes": [1, 2], "replacements": [{ "from": 2, "to": 3 }] }`
（`replacements` 只需包含幸存文本仍在引用的待删编号；无引用时传空数组）。
撤销响应中的 `undone.op` 为 `"renumber"` 或 `"remove"`（裁撤时另含 `deletes` 与 `replacements`）。
409 响应示例：

```json
{
  "error": {
    "code": "RENUMBER_CONFLICT",
    "message": "存在编号冲突，已拒绝写入。",
    "conflicts": [
      {
        "code": "TARGET_COLLISION",
        "message": "新编号 10 已被既有条款占用……",
        "from": 1,
        "to": 10,
        "positions": [{ "line": 12, "column": 1, "offset": 180 }]
      }
    ]
  }
}
```

## 项目结构

```
.
├── docker/entrypoint.sh   # 首启兜底：装依赖、构建、建数据目录
├── Dockerfile             # 多阶段：依赖安装 + 前端构建 -> 运行镜像
├── docker-compose.yml     # 一条命令、端口 3000、数据卷
├── server/                # Express + better-sqlite3
│   └── src/
│       ├── numerals.ts    # 中文/阿拉伯数字互转
│       ├── parser.ts      # “第X条”解析、定义/引用、缺失与重复检测
│       ├── renumber.ts    # 映射规范化、冲突校验、单遍重建（交换/环形安全）
│       ├── removal.ts     # 标题边界区块、引用图、影响分析、裁撤计划与冲突校验
│       ├── db.ts          # SQLite 建表与原子事务（改号/裁撤提交 / 撤销共用）
│       └── index.ts       # API 与静态资源服务
└── client/                # React + TypeScript + Vite
    └── src/
        ├── App.tsx        # 工作台主流程（改号 + 裁撤）
        └── components/    # 解析面板、映射编辑、裁撤面板/预览、预览、冲突提示、高亮文本
```

## 本地开发（不用 Docker）

要求 Node.js ≥ 20。

```bash
npm install          # 安装两个 workspace 的依赖（含 better-sqlite3）
npm run build        # 构建前端到 client/dist
npm start            # 启动 API 并托管前端，访问 http://localhost:3000
```

开发热更新（两个终端）：

```bash
npm run dev:server   # Express + tsx watch，:3000
npm run dev:client   # Vite dev server，:5173（/api 已代理到 3000）
```

本地默认数据库位于 `server/data/contract.db`，删除该文件即可重置全部数据。
