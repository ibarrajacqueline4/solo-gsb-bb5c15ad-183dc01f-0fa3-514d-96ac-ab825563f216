# 合同条款重编号工作台

粘贴含“第X条”定义与条款引用的合同纯文本，系统解析引用关系、标出**缺失引用**与**重复编号**；
提交“旧编号 → 新编号”的批量映射后，先给出**逐处变更预览**，确认后以**单个 SQLite 事务原子
同步**条款标题与正文引用。支持交换、环形改号以及 1/10 等前缀相近编号；检测到冲突时**拒绝写入**
并给出冲突位置。可**撤销**最近一次改号（栈式，可连续撤销），并**导出**处理后的文本。

技术栈：React + TypeScript（Vite）· Node.js + Express · SQLite（better-sqlite3）· Docker / Compose。

## 一条命令启动

```bash
docker compose up --build
```

首次运行会自动：构建并安装依赖 → 构建前端 → 创建 SQLite 数据库（自动建表）→ 启动服务。
随后打开 **http://localhost:3000** 即可使用。停止后数据保留在 Docker 卷 `contract-data` 中。

> 不想用容器？本地开发见文末“本地开发（不用 Docker）”。

## 使用流程

1. **粘贴文本**：把合同纯文本粘入文本框（可点“载入示例”体验，示例内含重复定义、缺失引用、
   第1条与第10条）。点击“解析并建立工作台”。
2. **检查解析结果**：
   - 行首（允许前导空白、后跟空白或标点）的“第X条”识别为**条款定义（标题）**；
   - 其余所有“第X条”出现识别为**引用**；
   - 引用了未定义编号 → ❌ 缺失引用；同一编号有多个标题 → 重复编号（标出首次/再次出现的行）。
3. **填写映射**：每行填写旧编号与新编号（正整数）。可点按钮快速生成“交换”或“环形改号”。
4. **生成预览**：逐处列出“标题/引用、行列位置、改动前后、上下文”，并可展开查看高亮后的全文。
5. **确认提交**：后端再次校验，通过后在一个事务内写入撤销历史并更新正文，保证原子性。
6. **撤销 / 导出**：撤销最近一次改号（恢复操作前正文并弹出历史栈顶）；导出当前文本为 `.txt`。

### 编号风格

- 同时支持**阿拉伯数字**（第1条、第12条）与**中文数字**（第一条、第十二条、壹拾贰条、含“两”）。
- 每处出现**沿用自身原有风格**：原文“第十条”改成 3 后写为“第三条”；原文“第10条”写为“第3条”。
- 交换与环形不依赖替换顺序：实现上以完整 token（带“第/条”定界）为单位重新扫描、单遍重建，
  因此“第1条”永远不会误伤“第10条”，1→2 与 2→1 同时提交也安全。

## 冲突拒绝规则（HTTP 409，响应含行列位置，不产生任何写入）

| 情形 | 说明 |
| --- | --- |
| 映射为空 / 行列格式非法 | 旧、新编号都必须是正整数 |
| 同一旧编号出现多次 | 一个源只能有一个目标 |
| 新编号在映射内重复 | 两个源不能争用同一目标 |
| 旧编号在文本中没有标题定义 | 引用不能作为改号源头 |
| 新编号撞上**未参与**本次映射的既有条款 | 会产生重复定义，拒绝并给出既有标题位置 |

已在映射内部的编号互换/环形（如 1→2、2→1，或 1→2→3→1）属于合法重排，会被正确接受。

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_PATH` | 容器内 `/data/contract.db` | SQLite 文件路径，启动时自动建库建表 |

Compose 已把 `/data` 挂载到命名卷 `contract-data`，容器重建后数据不丢失。

## HTTP API（摘要）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/analyze` | 无状态解析文本，返回定义/引用/问题 |
| POST | `/api/documents` | 建立工作台文档并解析 |
| GET | `/api/documents/:id` | 获取文档与最新解析 |
| PUT | `/api/documents/:id` | 手工修改原文（清空撤销栈） |
| POST | `/api/documents/:id/renumber/preview` | 逐处变更预览（只读，冲突返回 409） |
| POST | `/api/documents/:id/renumber/commit` | 原子提交改号 |
| POST | `/api/documents/:id/undo` | 撤销最近一次改号 |
| GET | `/api/documents/:id/export` | 导出处理后的纯文本 |

提交/预览请求体：`{ "mapping": [{ "from": 1, "to": 2 }, { "from": 2, "to": 1 }] }`。
409 响应示例：

```json
{
  "error": {
    "code": "RENUMBER_CONFLICT",
    "message": "存在编号冲突，已拒绝写入。",
    "conflicts": [
      {
        "code": "TARGET_COLLISION",
        "message": "新编号 10 已被既有条款占用……",
        "from": 1,
        "to": 10,
        "positions": [{ "line": 12, "column": 1, "offset": 180 }]
      }
    ]
  }
}
```

## 项目结构

```
.
├── docker/entrypoint.sh   # 首启兜底：装依赖、构建、建数据目录
├── Dockerfile             # 多阶段：依赖安装 + 前端构建 -> 运行镜像
├── docker-compose.yml     # 一条命令、端口 3000、数据卷
├── server/                # Express + better-sqlite3
│   └── src/
│       ├── numerals.ts    # 中文/阿拉伯数字互转
│       ├── parser.ts      # “第X条”解析、定义/引用、缺失与重复检测
│       ├── renumber.ts    # 映射规范化、冲突校验、单遍重建（交换/环形安全）
│       ├── db.ts          # SQLite 建表与原子事务（提交 / 撤销）
│       └── index.ts       # API 与静态资源服务
└── client/                # React + TypeScript + Vite
    └── src/
        ├── App.tsx        # 工作台主流程
        └── components/    # 解析面板、映射编辑、预览、冲突提示、高亮文本
```

## 本地开发（不用 Docker）

要求 Node.js ≥ 20。

```bash
npm install          # 安装两个 workspace 的依赖（含 better-sqlite3）
npm run build        # 构建前端到 client/dist
npm start            # 启动 API 并托管前端，访问 http://localhost:3000
```

开发热更新（两个终端）：

```bash
npm run dev:server   # Express + tsx watch，:3000
npm run dev:client   # Vite dev server，:5173（/api 已代理到 3000）
```

本地默认数据库位于 `server/data/contract.db`，删除该文件即可重置全部数据。
